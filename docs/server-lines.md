# 服务器公共线路管理

Motiquies Sign System 可为 [Motiquies Minecraft 服务器](https://motiquies.yuchan.moe/)提供共享线路资料。编辑器计划部署于 [sign.motiquies.yuchan.moe](https://sign.motiquies.yuchan.moe/)；这是计划地址，尚未验证上线。

公共线路保存在网站的静态文件 `data/lines.json`。管理员准备线路资料并通过网站部署发布，访客读取同一份列表。浏览器中的本地线路库独立保存个人草稿与副本。

## 管理员发布流程

1. 打开编辑器左侧「线路管理」，将来源选为「我的线路」，新建线路，填写中英文名、线路色、各站中英文名、编号、换乘、本站与方向。
2. 将每条准备发布的线路「保存到本地」。可反复创建多条线路；为换乘线路分别设置名称和颜色，避免不同线路误用同一 ID。
3. 点击「导出服务器线路列表」，下载 `lines.json`。它包含当前本地线路库中全部已保存线路，不包含未保存草稿；单条 `.railway-line.json` 文件与项目 JSON 不能替代它。
4. 检查下载文件的线路、站点和配色，将其作为网站的 `data/lines.json`。只放入准备公开的资料。
5. 使用正常的网站部署流程发布更新。例如提交替换后的文件，由网站托管系统部署；发布完成后在线路管理选择「服务器线路」，点击「刷新服务器列表」，确认条目和更新时间。

编辑器不会直接上传或改写网站文件。是否能发布由网站文件写入权限、仓库权限或部署权限决定，不提供客户端管理员密码或账号管理。普通访客即使导出自己的列表，也只有本地下载文件；将文件放到网站仍需相应部署权限。

更新公共线路不会批量修改访客已制作的牌面、当前项目中的线路快照或另存的本地副本。需要使用新资料时，访客重新选择服务器线路，再制作或更新相应标识。

## 访客使用

1. 打开「线路管理」，将来源从「我的线路」切换为「服务器线路」，点击「刷新服务器列表」。状态区显示线路条数、更新时间，以及可能的条目警告。
2. 在服务器列表中选择线路，检查站点、本站和方向。
3. 点击「用于制作车站标识」后选站添加标识；配色来源会自动切为「服务器线路」。如需线路图，选择横向或竖向后点击「放入牌面」；编辑已有线路图时按钮为「更新牌面」。这两种操作都不隐式保存本地线路。
4. 要保留个人修改版，点击「另存到我的线路」。副本使用新的线路 ID，之后在「我的线路」中编辑，不会覆盖服务器原条目。

刷新公共列表不会把全部线路写入本地库，也不会覆盖正在编辑的草稿。请求失败时会显示错误，并保留上次成功读取的目录；没有成功加载过时，应先排查地址或网络再重试。

| 内容 | 存放位置 | 修改与共享方式 |
| --- | --- | --- |
| 服务器公共线路 | 网站 `data/lines.json` | 管理员经网站部署替换，访客刷新读取 |
| 本地线路 | 当前浏览器的本地线路库 | 自己编辑、保存和删除，不影响公共列表 |
| 单条线路文件 | 下载的 `.railway-line.json` | 迁移一条线路的资料及所需换乘配色快照 |
| 项目文件 | 下载的项目 JSON | 保存整套牌面、布局和当前使用的线路资料 |
| 标识图片 | 导出的 SVG／PNG | 展示或自行处理为 Minecraft 贴图 |

## 列表文件格式

顶层 `format` 必须为 `railway-line-catalog`，`version` 必须为数字 `1`。`lines` 是完整线路对象数组，不是文件名、链接或单条线路文件包装。`updatedAt` 可省略；发布时建议提供 ISO 8601 时间字符串，便于访客确认版本。

以下为虚构示例，不代表已发布的服务器资料：

```json
{
  "format": "railway-line-catalog",
  "version": 1,
  "updatedAt": "2026-10-24T08:00:00Z",
  "lines": [
    {
      "id": "motiquies-line-9",
      "nameZh": "9号线",
      "nameEn": "Line 9",
      "color": "#713FAD",
      "stations": [
        {
          "id": "line-9-starport",
          "nameZh": "星港",
          "nameEn": "Starport",
          "code": "01",
          "transfers": "10号线"
        },
        {
          "id": "line-9-spruce-valley",
          "nameZh": "云杉谷",
          "nameEn": "Spruce Valley",
          "code": "02",
          "transfers": ""
        }
      ],
      "currentStationId": "line-9-starport",
      "direction": "forward",
      "relatedLines": [
        {
          "id": "motiquies-line-10",
          "nameZh": "10号线",
          "nameEn": "Line 10",
          "color": "#E97722"
        }
      ]
    }
  ]
}
```

每条线路使用与独立线路文件相同的线路模型：

| 字段 | 格式 |
| --- | --- |
| `id` | 非空字符串；公共列表内每条线路唯一，更新同一条线路时保留 |
| `nameZh`、`nameEn` | 中英文线路名字符串 |
| `color` | 十六进制线路颜色，如 `#713FAD` |
| `stations` | 最多256个站点；每站包含字符串 `id`、`nameZh`、`nameEn`、`code`、`transfers` |
| 站点 `id` | 同一线路内唯一，排序或改名时保留 |
| `currentStationId` | 本线路已有站点 ID，或 `null` |
| `direction` | `forward` 或 `backward` |
| `relatedLines` | 可选数组；只含实际换乘外线的 `id`、`nameZh`、`nameEn`、`color` 快照，不递归保存外线站点 |

上例的10号线快照只保留换乘名称与颜色，不会把10号线作为可选完整线路发布。若也要供访客选择10号线，需在 `lines` 数组中再加入它的完整线路对象。

空列表也合法：

```json
{
  "format": "railway-line-catalog",
  "version": 1,
  "lines": []
}
```

建议直接使用编辑器导出的列表，避免手工遗漏站点字段。管理员导出会严格验证线路与重复 ID；读取公共列表时，顶层格式或版本错误会拒绝加载，个别损坏线路会被跳过并报告。

## 部署和刷新

将 `data` 目录与 `index.html` 一起静态部署。默认请求地址相对于编辑器页面解析，因此托管在子目录时也应保留相应的 `data/lines.json` 路径。

每次刷新会重新请求文件并使用 `cache: no-store`，默认10秒超时。若发布后仍看到旧内容，检查托管平台或 CDN 上的文件是否更新，再刷新列表。直接以 `file://` 打开页面可能限制网络读取，建议通过 HTTP 服务使用。

计划的在线入口与服务器介绍页用途不同：`sign.motiquies.yuchan.moe` 用于部署编辑器，`motiquies.yuchan.moe` 是 Motiquies MC 服务器介绍页。
